# AGENTS.md

Compact guide for OpenCode sessions working in this repo. Read this before editing.

## Build & run

- **Build/compile:** `./gradlew compileJava` (quiet: `./gradlew compileJava --quiet`). Java 21 toolchain, Gradle Kotlin DSL.
- **Run the app:** `./gradlew bootRun`. Requires a local Neo4j with the **APOC** plugin installed and reachable at `bolt://localhost:7687`; an APOC probe at startup throws `Neo4jUnavailableException` (→ 503) if APOC is missing.
- **Tests:** `./gradlew test` is hermetic (no network except WireMock on localhost, no Neo4j, no Node) and writes a JaCoCo report to `build/reports/jacoco/test/`; it excludes `*IT` classes. Use `./gradlew compileJava` for the fastest main-only sanity check and `./gradlew compileTestJava` to compile tests. The real-model evals are guarded by system properties and skipped unless enabled (see below).
- **App-level flow tests:** `src/test/java/.../flow/` (`UploadFlowTest`, `ChatFlowTest`) are hermetic `@SpringBootTest`s on a random port. LLMs are faked by `FakeLlmServer` (WireMock, `app.models.*.base-url` = `http://localhost:<port>/v1`), Neo4j by `@MockitoBean` `Driver`/`Neo4jGraphWriter`/`CypherExecutor` (the context never connects to a database), and `QuestionRouter`/`AnswerJudge` by mocks. Extraction stubs match on request-body text because chunks run in parallel; agent stubs are an ordered WireMock scenario (agent requests carry a `tools` array). `UploadFlowTest` runs with resolution on (the writer's `findCandidates` / `applyResolution` are stubbed; resolution LLM stubs match on `Decide for each new entity`). `ChatFlowTest` includes the `conversationHistoryEnabled` regression (every tool round must still contain the user question).
- **UI tests:** `./gradlew jsTest` (part of `check`, skipped when `node` is not on the PATH) runs `src/test/js/*.test.js` with `node --test`; `alpine-stub.js` evaluates `trace.js`/`app.js` in the Node process with a captured `Alpine.data`.
- **Real-Neo4j tests (opt-in):** `./gradlew neo4jIt` runs the `*IT` classes (writer, injection safety, `CypherExecutor`, schema, APOC probe, entity resolution `EntityResolutionWriterIT`, cleanup `ResolveGraphIT`) against a **dedicated throwaway Neo4j**, default `bolt://localhost:7688` (`NEO4J_IT_URI` / `NEO4J_IT_USER` / `NEO4J_IT_PASSWORD`; defaults `neo4j` / `neo4j-admin`). The real graph is `bolt://localhost:7687` and **tests never target it**: `Neo4jItSupport` fails (never skips) unless the port is not 7687 *and* exactly one `(:KgTestInstance {id: 'kg-throwaway'})` sentinel node exists, then wipes everything except the sentinel before each test. One-time setup on the throwaway instance only: `cypher-shell -a bolt://localhost:7688 -u neo4j -p neo4j-admin "MERGE (:KgTestInstance {id: 'kg-throwaway'})"`. It needs APOC installed. `neo4jIt` writes `build/jacoco/neo4jIt.exec`; `./gradlew jacocoMergedReport` (run after `test neo4jIt`) merges both into `build/reports/jacoco/merged/`. There is no coverage gate.
- **Chat eval (on-demand):** `./gradlew chatEval` runs the real-model eval against the loaded HistoryOfIBM graph. Requires Neo4j + APOC reachable at `bolt://localhost:7687`. `OPENAI_API_KEY` is optional — application.yml inlines a default key (also feeding `spring.ai.openai.api-key`, without which Spring AI's auto-configured OpenAI beans hard-fail context startup). Non-deterministic; treat as a quality gate, not a CI gate. The LLM-as-judge runs through Spring AI's `Evaluator` API (`KnowledgeGraphJudgeEvaluator` wraps the domain judge; `pass = grounded && correct`, per-dimension in metadata), and a `FactCheckingEvaluator` pass adds an extra groundedness check on non-probe cases (~11 judge-side LLM calls/run: 6 judge + 5 fact-check). Judge/fact-check context is built from `ChatResponse.evidence()` — every `runReadCypher` call's rows across all turns, one document per query (never just the last query: agents often end with a `LIMIT 1` lookup, which previously caused false rowCount-floor and groundedness failures). Invariants aggregate over turns: skills/cypher are unioned (a follow-up turn may skip the Skill tool), and `minRowCount` checks the largest single query result. Probe cases are judged with a probe-specific rubric (`evaluateProbe`): grounded = does not fabricate the asked event — refutations with explicitly-labeled general-knowledge context pass (the strict all-facts-from-rows rubric fails refutations non-deterministically). `ChatEvalClient` uses a 15-min read timeout; a full tool loop against the remote model can exceed 5 min. A preflight (Neo4j + loaded `:Document`s + one LLM ping) fails fast with a clear message before any case runs. The judge defaults to the chat model; the advisory `FactCheckingEvaluator` pass is off by default (`-Deval.factcheck=true` enables it; it never fails a case); the judge client timeout is 300s (`eval.judge.timeout`). Set `-Deval.judge.base-url`/`api-key`/`model` (forwarded by the `chatEval` task) to grade with a different one. See `docs/specs/SPEC_eval.md`.
- **Jev client:** one `TypeSafeClient` bean from `spring-ai-starter-typesafe` (needs `spring.ai.typesafe.api-key`; with routing or judge enabled and no key the app fails at startup). Tests: `TypeSafeWireMockTest` stubs `POST /v1/systemone`; `TypeSafeConfigTest` loads the real `application.yml` through the starter. WireMock needs HTTP/1.1 against cleartext (see the test).
- **Intent gate (optional; `enabled: true` in the checked-in `application.yml`, off when the property is absent):** `app.routing.enabled=true` sends each chat prompt plus the recent conversation history to TypeSafe Jev as one `Choice` question (`TypeSafeIntentClassifier` through the shared `TypeSafeClient` from `spring-ai-starter-typesafe`; `typesafe/jev-1.13` via OpenRouter, same `OPENAI_API_KEY`; connection settings, 3s timeout and one retry within 5s are under `spring.ai.typesafe.*`, and the SDK appends `/v1/systemone` so `base-url` is `https://openrouter.ai/api`). The router's own block rule (`RouteDecision.decide`) stays; the SDK owns retries. Non-`GRAPH` probability mass >= `block-threshold` (0.9) skips the agent/tool loop and answers from the tool-free `directChatClient` (general knowledge, not from the graph; `route` on the response and a UI badge say so; falls back to the canned `RoutingReplies` text if that call fails); any failure fails open (`SKIPPED`). **Data egress:** with it on, a graph profile in the classifier instructions (loaded `:Document` filenames, top entity labels, and the 15 most-connected entity names; loaded at startup and refreshed every 60s by `GraphCatalog`), prompts and history (incl. assistant answers built from graph rows) go to third parties. Result is in `ChatResponse.route`. Eval: `OPENAI_API_KEY=... ./gradlew routingEval` (hard gate: no graph/golden prompt BLOCKED; last run 0 false blocks, 15/15 non-graph blocked at 0.9; `-Drouting.threshold=` to tune). See `docs/specs/SPEC_routing.md` (design history) and `docs/specs/SPEC_spring-ai-typesafe.md` (current client).
- **Answer judge (optional; `enabled: true` in the checked-in `application.yml`, off when the property is absent):** `app.judge.enabled=true` makes `ChatService.runAgent()` judge each agent answer with the library's `JevJudge` (`JevAnswerJudge.buildJudge`; same shared `TypeSafeClient`, `typesafe/jev-1.13`) as two `Score` criteria (groundedness, relevance; each must reach the top level, and an inconclusive criterion counts as LOW). The result is `ChatResponse.quality` (`status` `OK`/`LOW`/`SKIPPED`, `feedback` = the judge's rendered reason for LOW, `evidenceTruncated`) and a chip in the UI. A criterion Jev could not answer (`ERROR`) or a thrown error is `SKIPPED`. Advisory only: it never changes, retries or hides an answer; any failure => `SKIPPED`; the shared client's 3s timeout and one retry within 5s apply. Blocked/direct-model turns are not judged. **Data egress:** with it on, the full stored conversation history (up to 20 messages), the retrieved graph rows (up to `max-evidence-chars`, default 8000) and the answer go to OpenRouter and TypeSafe on every agent answer; it has its own flag, separate from routing. Eval: `OPENAI_API_KEY=... ./gradlew judgeEval` (hard gate: the six golden answers are never LOW or SKIPPED; reports false LOW on good answers and bad answers caught; last run 6/6 golden OK, 1/10 good flagged LOW, 10/10 bad flagged LOW). See `docs/specs/SPEC_judge.md` (design history) and `docs/specs/SPEC_spring-ai-typesafe.md` (current client).
- **Entity resolution (optional; `enabled: true` in the checked-in `application.yml`, off when the property is absent):** `app.resolution.enabled=true` puts `EntityResolutionService` between pass 1 and pass 2 (see Architecture). Off = the old `apoc.merge.node` path (no `:Entity`, no `MENTIONS`, no resolution); the pass 1 prompt changes (preferred labels from `PreferredLabels`, fullest names) and `elementId` apply either way. Settings: `candidate-limit` (5), `min-fulltext-score` (1.0, Lucene scores are not normalized; untuned), `batch-size` (20 entities per LLM call). The schema (`document_hash` constraint, `entity_name_norm` / `entity_match_key` indexes, `entity_names` full-text index) is created by the startup probe and again on the first upload if that failed. **Data egress:** ambiguous matches send entity names, descriptions and neighbour edge names to the extraction model (OpenRouter), the same provider and kind of data extraction already sends. A resolution LLM batch that fails or answers with references it was not offered creates those entities as new (`unresolvedEntities` in the response); the upload never fails on it. The resolution lock is in-process only (one app instance). See `docs/specs/SPEC_entity_resolution.md`.
- **One-time cleanup (`./gradlew resolveGraph`):** a `JavaExec` task (main class `resolve.ResolveGraphCommand`, no web server, routing/judge off, resolution on, in-memory H2) that **writes to the graph at `spring.neo4j.uri` (the real graph by default)**. Plan mode (default) first runs an idempotent migration (adds `:Entity` to nodes with `name_norm`, fills `match_key` / `aliases*`, creates `MENTIONS` from `source_doc`, creates the schema) and then writes `build/reports/resolve/plan.json` + `plan.md` without merging anything; clusters of one label joined by name / alias / match key are planned without the LLM, mixed-label or full-text clusters go to the LLM in cluster mode, and what it is unsure about is listed under "Needs review". Apply: take a dump (`neo4j-admin database dump`), then `./gradlew resolveGraph -Dresolve.apply=true -Dresolve.backupConfirmed=true`; it refuses without the plan or when any planned node changed or disappeared, merges each entry in its own transaction with `apoc.refactor.mergeNodes` (`mergeRels`), deletes the self-loops that creates, and writes `apply.md`. Other knobs: `-Dresolve.dir`, `-Dresolve.minFulltextScore`, `-Dresolve.candidateLimit`, `-Dresolve.maxClusterSize`. Nodes from before the migration lack `:Entity`, so **run plan mode once before uploading with resolution on**, or new uploads cannot see the old nodes.
- **No CI workflows** (`.github` absent). Branch: `user/jimmykw/dev`.
- The LLM endpoint and key are set in `src/main/resources/application.yml` via `OPENAI_API_KEY` / `NEO4J_PASSWORD` env vars (defaults are inlined). Extract and chat models both use `stealth/space-bunny-alpha` through OpenRouter (OpenAI-compatible base URL); other providers/models are left as commented alternatives in `application.yml`.

## Architecture

Single Spring Boot 4.0 + Spring AI 2.0 app. One synchronous endpoint:

`POST /api/knowledge-graph` (multipart, part `file` = PDF) → `GraphSummaryResponse` (counts by label/type, failedChunks, timing, and `entitiesCreated` / `entitiesMerged` / `unresolvedEntities`, zero when resolution is off; `nodeCount` = created + merged).

Flow (wired in `GraphController`, beans declared explicitly in `AppConfig.java` — **no `@Component` scanning**):
1. `PdfIngestionService` — SHA-256 hash, skip duplicate `:Document`, page guard, `PagePdfDocumentReader` + `TokenTextSplitter`. Chunks stay in memory (no `:Chunk` persistence).
2. `EntityExtractionService` (Pass 1) — per-chunk parallel LLM calls, dedupe on (normalized name, label). With resolution **off**, `extract` writes them via one batched `UNWIND` + `apoc.merge.node` query and builds `CanonicalIndex` from returned ids (correlated by `idx`). With it **on**, `extractEntities` writes nothing and:
   - `EntityResolutionService` (under one `ReentrantLock`) runs one batched candidate query (`Neo4jGraphWriter.findCandidates`: `name_norm` / `aliases_norm` / `match_key` hits plus `entity_names` full-text hits, each with 5 neighbour edges), classifies (`ResolutionClassifier`: a sole exact candidate with the same label merges without the LLM; cross-label, several exact, fuzzy-only and in-batch cross-label groups go to the LLM), asks `ResolutionPrompter` in parallel batches (short `n1`/`c1` refs, never element ids), plans (`ResolutionPlanner`: survivor label by `PreferredLabels.rank`, aliases union) and writes in one transaction (`applyResolution`: `apoc.create.node(['Entity', label])`, alias/label updates via `apoc.create.addLabels`/`removeLabels`, `(:Document)-[:MENTIONS {name, description}]->(e)`). `CanonicalIndex` maps the names **as written in this document** to the resolved element ids.
3. `RelationshipExtractionService` (Pass 2) — per-chunk parallel LLM calls with the canonical entity list injected into the prompt; resolve endpoints via `CanonicalIndex.lookup`, drop on `None`, dedupe, write via one batched `UNWIND` + `apoc.merge.relationship` query. Schema labels/rel types are recorded once per pass via `recordSchema`, not per write.

Entry point: `KnowledgeGraphApplication.java` (has `@ConfigurationPropertiesScan` so `AppProperties` is picked up).

## Critical conventions

- **Node ids are `elementId` strings**, never the deprecated `id()` (`CanonicalIndex`, `ResolvedRelationship.sourceId/targetId`, all writer return values, `documentId` in responses).
- **Entity graph shape (resolution on):** `(:Entity:<Label> {name, name_norm, match_key, aliases, aliases_norm, aliases_text, label, description, source_doc})`; `match_key` = `EntityNormalizer.matchKey` (normalized, punctuation and a leading "the" and trailing corporate suffixes stripped). Provenance is `(:Document)-[:MENTIONS]->(:Entity)`, one edge per mentioning document with that document's name and description; `source_doc` is only the first document. `MENTIONS` is in `:Schema` relTypes; `readTopEntityTypes` ignores `Entity` and `readTopEntityNames` leaves `MENTIONS` out of the degree. Queries that walk `(a)--(b)` reach `:Document` nodes now; the skills exclude them.

- **Dynamic Neo4j labels/relationship types are NEVER string-interpolated.** Cypher can't parameterize labels, so all dynamic writes go through **APOC procedures** (`apoc.merge.node`, `apoc.merge.relationship`) with the label/type passed as a parameter. This is the injection-safety mechanism — do not replace APOC calls with string-built Cypher. **But APOC itself wraps the label/type in unescaped backticks**, so labels and relationship types must pass `CypherIdentifiers.isSafe` (no backtick or control characters); the extraction services reject others and `Neo4jGraphWriter` refuses them with `IllegalArgumentException`.
- **APOC `apoc.merge.relationship` signature:** `apoc.merge.relationship(from, type, props, onMatchProps, to, onCreateProps)`. The 6th argument is a **map** (`{}`). Passing `true` (a boolean) throws a Cypher type error and silently kills the whole `foldLeft` because exceptions escape the merge loop. This was a real bug — keep the 6th arg a map.
- **Vavr everywhere** for control flow and collections (`io.vavr`): `Try` for fallible ops, `Option` for nullables, `io.vavr.collection.List`/`HashMap`/`HashSet`, `foldLeft` for reductions. Do not introduce `java.util.Optional` or `java.util.stream` in the pipeline. Convert Vavr `Map` → `java.util.Map` only at the controller response boundary (`.toJavaMap()`).
- **Per-chunk LLM failure is skip-and-continue**, counted in `failedChunks`, not a thrown exception. Only page-limit (> `app.max-pages` → 413; 100 in `application.yml`, falls back to 50 if unset) and Neo4j-down (→ 503) are hard-fail HTTP paths via `ApiExceptionHandler`.
- **Chat entity matching is alias-aware:** the `runReadCypher` description and the skills match `e.name_norm = toLower($name) OR toLower($name) IN e.aliases_norm`, and `source-attribution` cites every `MENTIONS` document (falling back to `source_doc`).
- **Relationship endpoint resolution is name+label, normalized** (`EntityNormalizer.normalize` = trim + lowercase ROOT). The LLM must emit endpoint names matching the canonical list; mismatches cause silent drops (logged at `warn`), not failures.

## Logging

`logging.level.net.jimmykw.knowledgegraph: DEBUG` is on by default in `application.yml`. The extraction services emit a funnel of INFO logs (candidate count → valid/rejected → created/not-created) plus per-item `Created node`/`Created relationship` (info), `Rejected`/`dropped` (warn), and `Skipped duplicate` (debug). When debugging "no relationships created", read the funnel logs in order — a gap between two INFO lines means an exception escaped the fold.

`ApiExceptionHandler` logs every handled exception (`@Slf4j`). If you add a new exception type, give it a handler that logs — the generic `Exception` handler logs with stack trace at `error`.

## Style

Java style rules live in `~/.claude/rules/java-code-style.md` (loaded via `opencode.json` `instructions`). Key points an agent gets wrong:
- Lombok `val` for all locals (never `var` or explicit types).
- `@UtilityClass` + **explicit `static`** on public methods.
- Records with `@With` for immutable data; `@RequiredArgsConstructor` + `private final` for service deps (no `@Autowired`).
- `Try.of(...)`/`Try.withResources(...)` over try/catch; `Option.of(x)` over null checks in functional pipelines.
- AssertJ (`assertThat`) only.
- Keep lines ≤ 150 chars; break at method-chain boundaries, not inside argument lists.
- Extract named helpers when a scoped block (lambda/switch arm/catch) exceeds ~8-10 lines.

## Gotchas

- The agent's `runReadCypher` rejects write keywords (`WRITE_PATTERN`) and, with a separate message, `LOAD CSV` and `CALL apoc.(load|import|export|cypher|periodic).` (`EXTERNAL_PATTERN`; a blocklist, not a sandbox). Neither scan understands string literals: `CONTAINS 'create'` is blocked as a write (known false positive, `@Disabled` test).
- Re-uploading the same PDF returns `SKIPPED_DUPLICATE` with zeroed counts and makes **no LLM calls**. To re-test extraction against the same file, delete the `:Document {hash}` node in Neo4j first, or change the bytes.
- Corrupt, password-protected or non-PDF bytes uploaded as a `.pdf` → `400` (`InvalidFileException`) and **no** `:Document` is written, so the hash stays free. A PDF that parses but has no text (image-only, blank) → `200` with `nodeCount=0` and a `:Document` is recorded. `:Document` nodes left by older failed parses stay; delete them by hash to retry.
- `docs/specs/SPEC_chat.md` documents the original design intent but has drifted from the code in places (e.g. it still shows the buggy `apoc.merge.relationship(..., true)` call). Trust the code over `docs/specs/SPEC_chat.md` when they conflict.
- The opencode.ai/zen/go endpoint **400s any request missing `x-opencode-session`**. Every `OpenAiChatModel` bean carries `OpenCodeGoHeaders.httpClientCustomizer()` (OkHttp interceptor adding the session header + `knowledge-graph/1.0` UA); `ChatService.chat()` scopes the whole tool loop in `OpenCodeGoHeaders.withSession(conversationId, …)` (ThreadLocal — safe because the sync OpenAI client runs interceptors on the calling thread). Extraction/judge calls fall back to a process-wide id. New `OpenAiChatModel` beans must add the same customizer.
- Never set `.conversationHistoryEnabled(false)` on the manual `ToolCallingAdvisor` in `ChatService` while `MessageChatMemoryAdvisor` is at its default order (+200 — upstream of the tool advisor at +300, i.e. outside the tool-call loop). With history disabled, Spring AI rebuilds every tool round after the first as `[system, lastToolResponse]`, dropping the user question and prior tool calls — the model stops querying and answers context-free. The framework only disables internal history when a memory advisor is **downstream** of the tool advisor (`DefaultChatClient.autoRegisterToolCallingAdvisor`: `conversationHistoryEnabled(!hasDownstreamMemoryAdvisor)`). This was a real regression — see the correction notes in `docs/superpowers/specs/2026-07-31-multi-turn-chat-history-design.md`.
